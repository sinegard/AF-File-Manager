# Release exceptions

## AF-EXC-0.41.1-RSS — approved 2026-09-22

- Approver: AF File Manager owner (`sinegard`), explicitly in the project conversation after the failed v0.41.0 CI bootstrap and the unchanged v0.41.1 functional candidate were reported. This approval is for **v0.41.1 only**.
- Rule and scope: `docs/RELEASING.md` requires the emulator performance gate before publication. The owner accepts only `coldStartAndFirstPaint.memoryRssAnonMaxKb.maximum` and `largeDirectoryFirstContent.memoryRssAnonMaxKb.maximum` above the unchanged limits in `performance/budgets.json`. The failed gate remains a failure. No time, frame, heap, security, signature, functional, or exact-artifact requirement is waived.
- Candidate evidence: application behavior measured from source `110fc55a2ee81cc1c95f16d1f78077f4a379b080` on API 36 `DCoreRemote_API36_Tablet` with an x86_64 ABI-specific minified benchmark package and seven iterations per scenario. Cold-start RSS reached **119,688 KiB** versus **110,000 KiB**; first large-directory content reached **155,696 KiB** versus **155,000 KiB**. All five benchmark scenarios executed without test failure, and every declared time, frame, heap, and other RSS metric stayed within its limit. A matched cold-start run of published v0.40.0 source `b1d33a51034b5bc4b7a0a097d46393107c4cd751` reached **116,392 KiB**. The v0.41.1 source differs from the measured application only in release version metadata, the CI `sdkmanager` bootstrap correction, and exception documentation; the feature implementation is unchanged.
- Affected users and risk: v0.41.1 users, especially devices with limited free memory, may see the app evicted or restarted more often. The measured candidate is about 3.2 MiB above the matched v0.40.0 cold-start result. This API 36 emulator result is not physical Android 8–15 or low-memory-phone acceptance, and no memory improvement is claimed.
- Compensating controls: 485 JVM tests completed with zero failures or errors and one existing skip; Android lint, the minified release build, dynamic runtime-class verification, Android 8 and Android 15 Quick Tunnel checks, the 30 MB Android 8-to-15 transfer, and focused issue tests passed locally. Publication still requires the exact downloadable CI draft APK to match the tag, version, ABI, SHA-256, and established v2/v3 certificate, plus the affected optimized runtime checks on the isolated emulator. Any failure there blocks publication.
- Expiry and follow-up: this exception ends with v0.41.1. Keep the budgets unchanged and investigate the cold-start RSS delta before a later release; do not copy this approval forward.
- Recovery: do not overwrite the signed v0.41.1 assets or move its tag. If a release defect is found, keep v0.40.0 available and publish a separately numbered corrective release after validation. This record authorizes no deletion, physical-phone installation, credential change, or root access.

## AF-EXC-0.40.0-RSS — approved 2026-09-18

- Approver: AF File Manager owner (`sinegard`), in the project conversation after the two measured RSS failures were reported. This approval is for **v0.40.0 only**.
- Rule and scope: `docs/RELEASING.md` requires the emulator performance gate before publication. The owner allows this one release to proceed with only `coldStartAndFirstPaint.memoryRssAnonMaxKb.maximum` and `largeDirectoryFirstContent.memoryRssAnonMaxKb.maximum` above the existing limits in `performance/budgets.json`. The budget values and verifier remain unchanged; the failed gate remains a failure. No other test, security, signature, or exact-artifact check is waived.
- Candidate evidence: source `033390f5259a0a97f7267f7cde6a17914e69d962`, API 36 `DCoreRemote_API36_Tablet`, seven iterations per scenario. Cold-start RSS reached **116,464 KiB** versus **110,000 KiB**; first large-directory content reached **166,680 KiB** versus **155,000 KiB**. All five benchmark scenarios executed without test failure, and all declared time, frame, heap and other RSS metrics stayed within their limits. The 2026-09-15 published-base diagnostic also exceeded these two limits (116,464 and 166,220 KiB respectively), but was not a fresh matched baseline and does not convert the candidate's failures into passes.
- Affected users and risk: v0.40.0 users, especially devices with limited free memory, may see the app evicted or restarted more often. The API 36 emulator is not physical Android 8–14 or low-memory-phone acceptance. No claim of improved absolute memory use is made.

The locally signed APK exercised nearby transfer, split APK, background playback, root-service contract and terminal failure paths; installed bytes matched the candidate. Publication still requires the **exact downloadable CI draft APK** to match the tag, version, SHA-256 and established v2/v3 certificate, plus affected optimized runtime checks on the isolated emulator. A failure there blocks publication.
- Expiry and follow-up: this exception ends with v0.40.0. Before another release, investigate the two RSS measurements and either meet the unchanged budgets or request a separately scoped owner decision with new evidence. Do not copy this exception forward. Close it only with a later passing measurement or an explicit superseding decision.
- Recovery: do not overwrite the signed v0.40.0 asset or move its tag. If a release defect is found, keep the prior v0.39.0 available and publish a separately numbered corrective release after verification. This record authorizes no deletion, phone installation, credential change, or root access.
